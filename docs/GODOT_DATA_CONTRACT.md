# Godot Data Contract

This file defines the Godot-specific data we must capture before production validation.

## Runtime dump

Generated by:

```sh
cd godot
godot --headless --path . --script res://scripts/DumpRuntimeData.gd
```

Expected output:

```text
godot/validation/runtime_dump.json
```

It records:

```text
Engine.get_version_info()
Engine.get_architecture_name()
OS name / CPU data
renderer project setting
RenderingServer adapter name/vendor if available
loaded table schemas and case counts
```

## Mesh API dump

Generated by:

```sh
godot --headless --path . --script res://scripts/DumpMeshData.gd
```

Expected output:

```text
godot/validation/mesh_api_dump.json
```

It confirms that the current Godot runtime can create an ArrayMesh from vertex and index arrays and that MeshDataTool can read back vertices, edges, and faces.

## Optional M4 candidate metrics

Generated by:

```sh
godot --headless --path godot --script res://stages/05_m4_candidate_metrics/DumpM4CandidateMetrics.gd
```

Expected output:

```text
godot/validation/05_m4_candidate_metrics/m4_candidate_metrics.json
```

This validates the synced optional M4 candidate table in the Godot data path.
It is not the production gate and does not prove official `Transvoxel.cpp`
equivalence.

This must be produced by the real LOD seam assembler, not by the current table gallery viewer.

Required fields:

```json
{
  "schema": "boqsc.transvoxel.godot_seam_metrics.v1",
  "status": "PASS",
  "seam_open_edges": 0,
  "invalid_triangles": 0,
  "degenerate_triangles": 0,
  "tested_face_directions": 6,
  "tested_fields": 5,
  "outer_boundary_edges": "allowed"
}
```
